# Производительность: сессия 16–17.11.2026

Цель: decode ≥ 15 tok/s, prefill ≥ 50 tok/s на Flint-40B-A2.5B, top-6,
lossless, это устройство. Цель не достигнута. Ниже измерения, физика
потолка, что сработало и что нет.

## 1. Итог

| режим | tok/s | условия |
|---|---:|---|
| normal top-6, 8 токенов | **2.40** | 47 °C, кэш 1024 МБ, io 8 |
| normal top-6, 16 токенов | **0.96** | 60 °C, тот же конфиг |
| normal top-6, 2 токена | 1.63 | 47 °C, холодный кэш |
| `--turbo` (LOSSY), 8 токенов | **3.52** | 50 °C, Q4_0 dense, top-2 |
| prefill, union-путь, T=224 | **4.53** | 49.4 с, батч 32 |
| prefill, bulk-регион, T=224 | 2.32 | 96.5 с, sequential 16 ГБ |
| prefill, T=128 (харнесс) | 6.01 | 21.8 с |

Пик normal на холодном телефоне: 2.40 tok/s на 8 токенах. Нагретый
телефон даёт 0.96–1.7 tok/s. Turbo добавляет около 45 %, но меняет выход
модели и остаётся LOSSY.

## 2. Методика

- Устройство: Snapdragon 8s Gen 4 (SM8735), 1× Cortex-X4 + 7× Cortex-A720,
  15.2 ГБ RAM, Android/Termux, UFS.
- Модель: `flint-UD-Q3_K_XL.gguf`, 18.49 ГБ, 49 слоёв, 256 экспертов,
  top-6, hidden 2048, ffn эксперта 512, shared 1024.
- Запуск: `scripts/safe_run.sh`, один процесс, `MemAvailable > 4000` МБ
  перед стартом, AHB ≤ 4096 МБ, кэш ≤ 2048 МБ.
- Обязателен `termux-wake-lock`. Без него Android усыпляет процесс:
  первый baseline дал 1.12 tok/s и рваные столы 480 мс на слой. С wake
  lock те же слои идут 2 мс, но телефон быстро нагревается.
- Температура: cpu-зоны 46–72 °C. При 60 °C и выше частоты падают до
  1.2–1.7 ГГц, dense-поток падает с 12.6 до 4.2 ГБ/с.
- Любой замер без температуры, wake lock и числа токенов считается
  недействительным.

## 3. Бюджет токена

`qstat` по модели:

| роль | ГБ |
|---|---:|
| эксперты | 16.945 |
| attention | 0.891 |
| output | 0.327 |
| embedding | 0.327 |
| всего | 18.49 |

На один токен normal top-6:

- плотные веса после Q8_0: **1.74 ГБ**;
- эксперты: 6 из 256 × 3 проекции × 47 слоёв = **0.377 ГБ**;
- итого **2.12 ГБ/токен**.

Цель 15 tok/s = 66.7 мс/токен. Для неё нужна устойчивая полоса
**31.8 ГБ/с** при 100 % попадании экспертов и нулевых накладных. Даже при
25 ГБ/с потолок равен 11.8 tok/s. Измеренная устойчивая полоса: 4.2–12.6
ГБ/с. Разрыв не закрывается настройками кэша.

Prefill T=512 требует прочитать регион экспертов всех слоёв, около 16 ГБ.
При UFS 1.4 ГБ/с это 11.4 с только на I/O, то есть 45 tok/s до вычислений.
Union-путь T=224 читает меньше, но даёт 4.53 tok/s. Bulk-путь прочитал
16 ГБ и дал 2.32 tok/s: sequential-чтение не компенсировало лишние байты.

## 4. Что сделано

| изменение | результат |
|---|---|
| hot-веса: 391 буфер → 52 сегмента по 32 МБ (`TOKSHIT_HOT_SEG_MB`) | dense microbench 14.5 → 17.7 ГБ/с (+22 %); decode 1.87 → 1.92 tok/s в шуме |
| fusion: router + shared gate/up одним `run_segs`, dense gate/up одним | минус два барьера на MoE-слой, минус повторный `quantize_into` |
| `--turbo`: top-2 + Q4_0 dense + кэш 1024 + O_DIRECT | 3.52 tok/s, LOSSY, не normal |
| prefill-bulk: sequential-чтение региона слоя | opt-in, на T=224 хуже union-пути |
| bench harness: `scripts/bench_matrix.sh` | decode/prefill/A-B, JSON/CSV, температура, regression gate |
| wake lock и тепловой протокол | объясняют разброс 1–3 tok/s |
| `[gen-only]` underflow, timeout-сироты, цвет TUI | исправлены |

Тесты: **161 кейс / 7715 проверок**, все зелёные. Линкер документации:
19 файлов, 86 локальных ссылок, 0 битых.

## 5. Отрицательные результаты

- **Bulk prefill** на T=224: 96.5 с против 49.4 с у union. Читает
  325–379 МБ на слой, копирует 120–160 МБ. Для T=224 union около 100
  экспертов, то есть bulk читает в 2.5 раза больше байтов. Sequential
  полоса не настолько выше random, чтобы это окупить.
- **`--fast` (снят)**: cache 0 и page cache вместо O_DIRECT давали меньше,
  чем turbo с кэшем и O_DIRECT. Флаг удалён, `--spec-fast` остался
  отдельным LOSSY-пресетом.
- **Спекуляция**: полный verify расширяет union экспертов и не обгоняет
  normal. Оставлена выключенной.
- **mmap-dense** (`TOKSHIT_HOT=0`): page cache не удерживает 1.74 ГБ,
  0.8–1.6 tok/s.
- **AHB `read-often`**: 3.1 ГБ/с против 5.2 у `read-rarely`.
- **Кэш 2–3 ГБ**: hit-rate растёт на 8 п.п., tok/s не растёт, память
  уходит в reclaim.
- **`TOKSHIT_IQ2ROW=1` + `TOKSHIT_I8MM=1`**: 0.53 tok/s на 8 токенах при
  45 °C против 2.40 в baseline. Двухстрочный IQ-путь медленнее, флаги
  остаются выключенными.

## 6. Почему 15/50 не достигнуты

1. Плотные веса 1.74 ГБ читаются на каждом токене. При 12.6 ГБ/с это
   138 мс, уже меньше 7 tok/s.
2. Эксперты добавляют 0.377 ГБ и 200–700 мс на нагретом телефоне.
3. Телефон троттлит через несколько секунд нагрузки. На 60 °C dense
   падает до 4.2 ГБ/с, эксперт-путь до 0.5–2 ГБ/с.
4. Prefill упирается в UFS и в полный регион экспертов. Union-путь
   зависит от длины промпта, bulk-путь читает лишние байты.
5. 15 tok/s требует 31.8 ГБ/с устойчиво, 50 prefill требует ≥3.5 ГБ/с
   sequential плюс GEMM. Измеренный потолок устройства ниже.

Это предел связки «Flint-40B-A2.5B IQ3 + Snapdragon 8s Gen 4 + UFS +
15.2 ГБ RAM» при текущем кванте и top-6. Дальше нужны другие рычаги:
Q6_K/Q5_K ядра вместо Q8_0, i8mm GEMM для prefill, sidecar-layout
экспертов, внешнее охлаждение. Без смены одного из этих условий 15/50
остаются недостижимыми.

## 7. Воспроизведение

```sh
termux-wake-lock
TOKSHIT_MIN_AVAIL_MB=1800 scripts/safe_run.sh env GGUF_TIME=1 \
  TOKSHIT_PROF=1 build/tokshit --temperature 0 --cache-mb 1024 \
  --io-threads 8 --pool-workers 7 MODEL "привет" 8

TOKSHIT_MIN_AVAIL_MB=1800 scripts/safe_run.sh build/tokshit --turbo \
  --temperature 0 MODEL "привет" 8

TOKSHIT_PREFILL_BATCH=32 scripts/safe_run.sh build/tokshit --temperature 0 \
  --cache-mb 1024 --io-threads 8 --pool-workers 7 \
  MODEL --prompt-file /home/prompt128.txt 1
```

Перед замером проверить `/sys/class/thermal/thermal_zone*/temp` и
`MemAvailable`. После каждого прогона дать телефону остыть. Иначе
сравниваются не конфиги, а тепловые режимы.
