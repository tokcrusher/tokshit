# Рантайм: от файла до токена

`tokshit` — специализированный C++20 ARM64-рантайм для MoE-моделей, которые
больше оперативной памяти устройства. Он держит плотные веса в быстрой
памяти, стримит экспертов с флеша и считает forward одним проходом на токен.

Этот документ — сквозной путь: загрузка, forward, MoE, кэш, I/O, AHB, пул и
метрики. Карта модулей и инварианты — в
[ARCHITECTURE.ru.md](ARCHITECTURE.ru.md); форматы весов — в
[QUANTIZATION.md](QUANTIZATION.md); ядра — в [KERNELS.md](KERNELS.md).

## 1. Общая схема

```text
                 ┌──────────────┐
   model.gguf ──▶ │  GGUF+mmap   │
                 └──────┬───────┘
                        │ Meta: base, in_dim, out_dim, rb, quant
                        ▼
   ┌────────────────────────────────────────────────────────┐
   │ Model                                                  │
   │  embed ─▶ 49 × layer ─▶ final norm ─▶ output matvec    │
   │             │                                          │
   │             ├─ attention: qkv, RoPE, KV, softmax       │
   │             └─ FFN: dense или MoE                      │
   │                          │                             │
   │                          ├─ router top-6               │
   │                          ├─ ExpertIo / ResidentCache   │
   │                          ├─ gate/up ─▶ SwiGLU ─▶ down   │
   │                          └─ shared expert              │
   └────────────────────────────────────────────────────────┘
                        │
                        ▼
                 logits 150144 ─▶ sampling ─▶ token
```

## 2. Загрузка

`Model::load(path, options)`:

1. открывает GGUF и маппит файл (`Gguf::open`, `mmap_file`);
2. читает `flint.*`: число блоков, dense/MoE, hidden, головы, окно, rope;
3. строит `Layer` с `Meta`-смещениями в mmap;
4. считает бюджеты: общий кэш `TOKSHIT_EXPERT_CACHE_MB`, на слой
   `total / n_moe`;
5. создаёт `ResidentCache`, `FreqState` и `Workspace`;
6. инициализирует AHB-пул для кэша экспертов, если бюджет не 0;
7. создаёт `ExpertIo` с фоновыми читателями;
8. копирует плотные веса в hot-хранилище (`collect_hot`).

Тяжёлого копирования, кроме norm-векторов и hot-весов, нет.

### Горячие веса

`collect_hot()` собирает плотные тензоры: attention q/k/v/o, плотный FFN,
shared expert, роутер и `output.weight`. После Q8_0 это 1.74 ГБ в 52
сегментах по 32 МБ. Они читаются на каждом токене, поэтому лежат в
AHB/dma-buf и не вытесняются потоком экспертов.

`TOKSHIT_HOT=0` оставляет их в mmap. После копии page cache модели
сбрасывается (`POSIX_FADV_DONTNEED`), чтобы память ушла кэшу экспертов;
отключается через `--drop-cache=0`.

При копировании работает `TOKSHIT_HOT_CONV` (по умолчанию `1`): тензоры
без NEON-ядра (`Q5_K`, `Q6_K`, `BF16`) переквантовываются в `Q8_0`.
Подробности и A/B — в [QUANTIZATION.md](QUANTIZATION.md).

## 3. Один токен

`token_logits(token, kv, pos, out)`:

1. деквантит строку эмбеддинга прямо в `ws.x`;
2. собирает rope-таблицу в `ws.rope_table` без аллокаций;
3. вызывает `layer()` для каждого из 49 блоков;
4. делает финальный RMSNorm и matvec в `out` (словарь 150144).

В батчевом пути (`token_logits_batch`) то же самое для нескольких строк:
активации и KV обрабатываются пачкой, плотные веса переиспользуются.

`Workspace` живёт всё время генерации:

```cpp
struct Workspace {
  std::vector<float> x, hn, q, k, v, attn, o, hf;
  std::vector<float> g, u, dd, moe, logits, scores;
  std::vector<ActQ8> acts;
};
```

`layer()` и `token_logits()` не выделяют память.

## 4. Слой

### Attention

- RMSNorm входа;
- q/k/v одним `run_segs` — один барьер на три матвека;
- per-head RMSNorm для q и k;
- RoPE, если слой включён в `rope_on_`;
- дописывание k/v в KV-кеш;
- scores + attention sink, softmax, взвешенная сумма V;
- sliding window, если слой включён в `swa_`;
- `attn_o` и residual.

### FFN

Первые два блока — плотные: gate/up, SwiGLU, down.

Остальные 47 — MoE:

1. роутер `gate_inp` (BF16, 256 логитов);
2. top-6 по логитам;
3. веса через sigmoid и нормализацию;
4. параллельная загрузка `3 * n_used` срезов;
5. фаза A: gate/up одним `run_segs`, затем SwiGLU;
6. фаза B: down одним `run_segs`;
7. взвешенная сумма и shared expert (плотный MLP ширины 1024);
8. residual.

Константы промпта: `USER = 150003`, `ASSISTANT = 150004`. Префилл —
`USER + encode(prompt) + ASSISTANT`; `max_new` по умолчанию 12.

## 5. KV-кеш

`KVCache` — два сплошных сляба `k` и `v`. Слой `l` начинается со смещения
`l * cap * stride`; `stride = kv_dim * sizeof(dtype)`. Позиции абсолютные,
строки перезаписываются. `truncate_all(pos)` откатывает кеш без пересылок —
это использует спекулятивный цикл.

Спекулятивный путь держит отдельный f16 KV: 2К контекста ≈ 195 МБ на k+v.
Детали — в [SPEC_KV.md](SPEC_KV.md).

## 6. Кэш экспертов

`ResidentCache` послойный: у каждого слоя свой map и intrusive LRU-список,
эвикция O(1). Ключ — `(proj << 32) | expert`, где `proj` = 0/1/2
(gate/up/down). Бюджет слоя — `total_budget / n_moe`.

- бюджет 0 — «direct»: span смотрит прямо в mmap, ничего не копируется;
- иначе `ExpertIo::load` сначала проверяет кэш, потом читает;
- `pin_hot_experts(k)` после префилла добавляет самые частые эксперты
  последовательными `pread`-батчами (до 64 МБ за чтение);
- `TOKSHIT_PREFETCH` включает предсказание по прошлому токену; на телефоне
  оно примерно вдвое медленнее, поэтому по умолчанию выключено.

Большой кэш не гарантирует рост tok/s: при равномерном роутинге 2–3 ГБ
добавляют ~8 п.п. попаданий, но память уходит в reclaim. Рабочая точка —
512 МБ.

## 7. I/O экспертов

`ExpertIo` держит `O_DIRECT`-дескриптор, выровненные bounce-буферы и пул
читателей.

- `load()` — спрос: кэш, затем чтение в вызывающем потоке. Так у диска
  больше глубины очереди, чем у пары фоновых читателей.
- `demand_async()` — заказать чтение без ожидания; `take_expert()` ждёт
  результат и берёт блок из кэша.
- `inflight_` не даёт прочитать один блок дважды: второй запрос ждёт уже
  едущее чтение.
- `prefetch()` — отдельная очередь предсказаний; `new_epoch()` на новом
  токене выбрасывает устаревшие предсказания.
- окно чтения выравнивается по `st_blksize`; невыровненный хвост копируется
  из bounce-буфера.
- ошибка чтения не ломает токен: `resident_expert` возвращается к mmap.

`O_DIRECT` не ускоряет диск сам по себе. Он не даёт экспертам вытеснять
плотные веса из page cache; поэтому в исторических длинных прогонах с кэшем
512 МБ декод шёл 2.0–2.7 tok/s, а без кэша — 1.24–1.37. Текущая рабочая
точка — 2.40 tok/s на холодном телефоне; цифры сравнимы только внутри
одной сессии.

## 8. AHB

Android под давлением отправляет анонимные страницы в ZRAM, и каждое чтение
плотных весов начинает платить за распаковку. `AHardwareBuffer` — dma-buf:
он не свопится и не вытесняется как anon-память. Это даёт стабильные
задержки и убирает ZRAM/swap.

Доступ — через `dlopen("libandroid.so")`, а не `-landroid`: бинарь с
`-landroid` требует версионированный `LIBANDROID vN`, а stub в Termux
собран без version-узлов. `dlopen` обходит и линковку, и проверку версии.

Бюджет:

- один на процесс, по умолчанию **5120 МиБ** (`TOKSHIT_AHB_MAX_MB`);
- его делят hot-веса и пул кэша экспертов;
- `reserve_ahb` отказывает, если после аллокации останется меньше 1 ГиБ
  `MemAvailable`;
- hot-веса — 52 сегмента по 32 МБ (`TOKSHIT_HOT_SEG_MB`), 1.74 ГБ: gralloc
  отвергает один буфер на 1.74 ГБ (`rc=-129`);
- пул экспертов — слябы по **16 МиБ** (`TOKSHIT_AHB_SLAB_MB`) и классы
  размеров, равные срезам gate/up/down; ленивый, слябы появляются после
  первых выборов роутера;
- пул получает **весь** бюджет кэша экспертов (`TOKSHIT_EXPERT_CACHE_MB`);
  его сжимают только глобальный лимит `TOKSHIT_AHB_MAX_MB` и резерв
  `MemAvailable`. Malloc-фолбэк ограничен 256 МиБ;
- `TOKSHIT_AHB=0` выключает AHB: hot-веса и кэш идут в malloc;
- `TOKSHIT_AHB_USAGE=rare|often`, по умолчанию `rare`. На этом устройстве
  `often` даёт некэшируемый mapping: 3.10 против 5.21 ГБ/с.

Полоса: 328 КБ блоки читаются на 25.7 ГБ/с против 21.7 у malloc, но поток
1.74 ГБ по 52 сегментам — ~5.2 ГБ/с. AHB оптимизирует не полосу отдельных сегментов, а стабильность
памяти: убирает ZRAM/swap и выравнивает задержки.

## 9. Пул потоков

`TaskPool` — синглтон с постоянными потоками и busy-wait барьером.

- `TOKSHIT_POOL_WORKERS` задаёт число воркеров (по умолчанию `nproc - 1`);
- главный поток всегда участвует;
- во время декода `set_active(true)` держит простаивающих воркеров в spin,
  а не в `sleep`;
- `TOKSHIT_POOL_PIN` прибивает воркеры к ядрам;
- `TOKSHIT_POOL_RT` пробует `SCHED_FIFO` (на Android обычно отказ);
- `TOKSHIT_MAIN_CPU` задаёт ядро главного потока при пиннинге.

Пул не является узким местом полного декода: короткие прогоны на 4–8 слоях
дают 12–24 tok/s и 25+ ГБ/с. В полном прогоне `GGUF_TIME=1` показывает
`load` и `downwait` — это ожидание экспертов, а не барьер.

## 10. Метрики

Счётчики — `std::atomic<uint64_t>` наносекунд, `std::chrono::steady_clock`.
Имена совпадают с форматом профилировщика:

| счётчик | что измеряет |
|---|---|
| `t_attn`, `t_attn_mm`, `t_attn_core` | attention целиком, matvec, softmax |
| `t_ffn`, `t_expert`, `t_shexp` | FFN, эксперты, shared expert |
| `t_router` | роутер |
| `t_load`, `t_down_wait` | загрузка экспертов и ожидание down |
| `t_head`, `t_embd`, `t_mm` | голова, эмбеддинг, matvec |
| `c_mm_bytes` | прочитанные байты матвека |
| `c_expert_hit/miss` | попадания кэша |
| `c_expert_union/passes` | уникальные эксперты на проход MoE |

Флаги: `GGUF_TIME=1` включает таймеры, `TOKSHIT_PROF=1` обнуляет метрики
после префилла, `--expert-stats` печатает union и hit-rate.

`c_expert_hit/miss` считаются и в одиночном, и в батчевом/спекулятивном
пути: `demand_async` вернул блок из кэша — hit, иначе — miss. Union
экспертов чанка учитывается по числу заказанных срезов, формат совпадает с
одиночным путём.

## 11. Ошибки

Ядро собрано с `-fno-exceptions -fno-rtti`. `Result<T>` — variant из
значения или `Error`; `TOKSHIT_TRY` — аналог `?`. Горячий путь ошибок не
создаёт: предусловия проверяются при загрузке. Исключений в загрузчике и
токенизаторе тоже нет.

## 12. Настройки, которые чаще всего нужны

| задача | флаги |
|---|---|
| обычный декод | `--cache-mb 512 --temperature 0` |
| без hot-копии | `--hot=0` |
| без AHB | `TOKSHIT_AHB=0` (env) |
| меньше памяти | `--cache-mb 256 --io-threads 1 --hot=0` |
| профиль фаз | `GGUF_TIME=1 --expert-stats` |
| сравнение конфигов | `scripts/ab.sh` |

Полная таблица флагов и переменных — в [CLI.md](CLI.md).
