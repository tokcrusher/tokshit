из кода загрузчика.

| параметр | значение |
|---|---|
| блоки | 49: 2 dense + 47 MoE |
| эксперты | 256 на MoE-слой, top-6 |
| hidden | 2048 |
| ffn эксперта | 512 |
| shared expert | 1024 |
| внимание | 32 q-головы, 4 kv, head_dim 128 |

## модули

- `gguf.cpp` — парсит заголовок, метаданные и таблицу тензоров. Файл маппится
  один раз, веса — span'ы в это отображение.
- `mmap.cpp` — RAII над `mmap` плюс best-effort `madvise`/`mlock`. Android
  может отказать, поэтому вызовы не считаются гарантией.
- `quant.cpp`, `dequant.cpp` — раскладка блоков и де-квант. `dequant_into`
  нужен холодным путям и эталонам; горячий путь считает прямо по квантам.
- `compute/kernels_scalar.cpp` — скалярный эталон.
- `compute/kernels_neon_dotprod.cpp` — NEON dotprod; компилируется отдельным
  TU с `-march=armv8.2-a+dotprod+fp16+lse`.
- `compute/kernels_dispatch.cpp` — выбор ядра на старте.
- `compute/kernels_batch.cpp`, `attn_batch.cpp` — батчевые matvec и attention
  для спекулятивного пути.
- `model.cpp` — загрузка, forward, MoE, hot-веса, кэш, метрики.
- `model_batch.cpp` — батчевый forward (`token_logits_batch`).
- `expert_io.cpp` — фоновые чтения экспертов, `O_DIRECT`, дедупликация.
- `ahb.cpp` — AHardwareBuffer: hot-веса и пул слотов кэша экспертов.
- `pool.cpp` — постоянный пул воркеров со spin-барьером.
- `sampling.cpp` — temperature/top-k/top-p, greedy, UTF-8-обёртка.
- `reasoning.cpp` — бюджет thinking-токенов и принудительный `</think/>`.
- `tokenizer.cpp` — BPE.
- `spec_loop.cpp` — спекулятивный цикл.
- `main.cpp` — CLI: флаги, пресеты, режимы.
- `src/tools/` — qstat, kbench, vcheck, bwbench, pbench, ahbtest.

## загрузка

`Model::load`:

1. открывает GGUF и маппит файл;
2. читает ключи `flint.*` (block_count, expert_count, hidden, ffn, паттерны
   attention);
3. строит `Layer` с `Meta`-смещениями в mmap;
4. считает бюджеты: общий кэш `TOKSHIT_EXPERT_CACHE_MB`, на слой
   `total / n_moe`;
5. создаёт `ResidentCache`, `FreqState`, `Workspace`;
6. инициализирует AHB-пул для кэша экспертов (если бюджет не 0);
7. создаёт `ExpertIo` с фоновыми читателями.

Тяжёлого копирования нет, кроме norm-векторов. Отдельно `collect_hot()`
копирует плотные веса: attention q/k/v/o, dense ffn, shared expert, роутер,
`output.weight` — 52 сегмента по 32 МБ, 1.74 ГБ. `Meta.base` после этого указывает либо
в mmap, либо в hot-хранилище; `meta_bytes()` выбирает по флагу `hot`.

`TOKSHIT_HOT=0` оставляет плотные веса в mmap. По умолчанию после копии
page cache модели сбрасывается (`POSIX_FADV_DONTNEED`), чтобы память ушла
кэшу экспертов.

При копировании `TOKSHIT_HOT_CONV=1` (по умолчанию) переквантовывает
плотные тензоры без NEON-ядра (`Q5_K`, `Q6_K`, `BF16`) в `Q8_0`.

## один токен

`token_logits(token, kv, pos, out)`:

1. де-квантует строку эмбеддинга прямо в `ws.x`;
2. собирает rope-таблицу в `ws.rope_table` без аллокаций;
3. вызывает `layer()` для каждого из 49 блоков;
4. делает финальный rmsnorm и matvec в `out` (словарь 150144).

В батчевом пути (`token_logits_batch`) то же самое, но активации и KV
обрабатываются сразу для нескольких строк.

## слой

`layer()` сначала считает attention:

- rmsnorm;
- qkv одним `run_segs`;
- q/k norm по головам;
- rope, если `rope_on_[layer]`;
- дописывает k/v в KV;
- scores + softmax с attention sink;
- o-matvec.

Потом FFN:

- dense-слой (первые 2): gate/up, swiglu, down;
- MoE-слой: роутер `gate_inp` (BF16, 256 логитов), top-6, веса через sigmoid
  и нормализацию, затем три проекции каждого эксперта (gate/up/down) и
  shared expert.

Эксперты грузятся через `resident_expert()` / `take_expert()`. Gate и up
считаются батчем `run_segs`, активация квантуется один раз на эксперта,
down — после swiglu. Shared expert — обычный плотный MLP размерности 1024.

## matvec и сегменты

Всё выражается через `Seg`: байтовый span весов, тип кванта, вход, уже
проквантованная активация и выход. `run_segs` режет сегменты на задачи по
16 или 32 строки и кидает их в пул. Вызывающий поток тоже берёт задачи.

Активация квантуется один раз на вход matvec (`quantize_into`) и
переиспользуется всеми сегментами. Поэтому на сегмент нет аллокации, а
`layer()` и `token_logits()` не выделяют память.

## кэш экспертов

`ResidentCache` послойный: у каждого слоя свой map и intrusive LRU-список,
эвикция O(1). Ключ — `(proj << 32) | expert`, где `proj` 0/1/2 =
gate/up/down. Бюджет слоя — `total_budget / n_moe`.

- бюджет 0 — «direct»: span смотрит прямо в mmap, ничего не копируется;
- иначе `ExpertIo::load` сначала проверяет кэш, потом читает;
- `pin_hot_experts(k)` после префилла добавляет самые частые эксперты
  последовательными `pread`-батчами (до 64 МБ за чтение);
- `TOKSHIT_PREFETCH` включает предсказание по прошлому токену; на телефоне
  оно примерно вдвое медленнее.

## I/O экспертов

`ExpertIo` держит `O_DIRECT`-дескриптор (если открылся и прошёл проверку
против буферизованного чтения), выровненные bounce-буферы и пул воркеров.

- `load()` — спрос: кэш, потом чтение в вызывающем потоке. Так у диска
  больше глубины очереди, чем у пары фоновых читателей.
- `demand_async()` — заказать чтение без ожидания; `take_expert()` ждёт
  результат и берёт блок из кэша.
- `inflight_` не даёт прочитать один блок дважды: если чтение уже едет,
  второй запрос ждёт его.
- `prefetch()` — отдельная очередь предсказаний; `new_epoch()` на новом
  токене выбрасывает устаревшие предсказания.
- окно чтения выравнивается по `st_blksize`; невыровненный хвост копируется
  из bounce-буфера.
- ошибка чтения не ломает токен: `resident_expert` падает обратно на mmap.

## AHB

Зачем: Android под давлением отправляет анонимные страницы в ZRAM. Тогда
каждое чтение плотных весов платит за распаковку. `AHardwareBuffer` — это
dma-buf: он не свопится и не вытесняется как anon-память.

Доступ: `dlopen("libandroid.so")`, а не `-landroid`. Бинарь с `-landroid`
требует `LIBANDROID vN`, а stub в Termux собран без version-узлов, поэтому
линковка падает ещё до `main`. `dlopen` обходит и линковку, и проверку версии.

Бюджет:

- один на процесс, по умолчанию **5120 МиБ** (`TOKSHIT_AHB_MAX_MB`);
- его делят hot-веса и пул кэша экспертов;
- `reserve_ahb` отказывает, если после аллокации останется меньше 1 ГиБ
  `MemAvailable`;
- hot-веса — **52 сегмента по 32 МБ** (`TOKSHIT_HOT_SEG_MB`), 1.74 ГБ.
  Один общий буфер на 1.74 ГБ gralloc отвергает с `rc=-129`;
- пул экспертов — слябы по 16 МБ (`TOKSHIT_AHB_SLAB_MB`) и классы размеров,
  равные срезам gate/up/down. Ленивый: слябы появляются, когда роутер
  реально начал выбирать экспертов;
- пул получает весь бюджет кэша экспертов; всё вместе ограничено
  глобальными 5120 МиБ;
- malloc-фолбэк кэша ограничен **256 МиБ**, чтобы «AHB + сколько получится
  malloc» снова не привёл к OOM;
- `TOKSHIT_AHB=0` выключает AHB полностью: hot-веса и кэш идут в malloc;
- `TOKSHIT_AHB_USAGE=rare|often`, по умолчанию `rare`. На этом устройстве
  `often` даёт некэшируемый mapping: поток hot-весов 3.10 против 5.21 GB/s.

AHB не ускоряет сам по себе: 328 КБ блоки читаются на 25.7 GB/s против
21.7 GB/s у malloc, а полный поток 1.74 ГБ по 52 сегментам — только ~5.2 GB/s.
Польза AHB — отсутствие ZRAM/swap и стабильные задержки.

## пул

`TaskPool` — синглтон с постоянными потоками и busy-wait барьером.
`TOKSHIT_POOL_WORKERS` задаёт число воркеров (по умолчанию `nproc - 1`),
главный поток всегда участвует. Во время декода вызывается
`set_active(true)`, чтобы простаивающие воркеры крутились, а не спали.
`TOKSHIT_POOL_PIN` прибивает воркеры к ядрам, `TOKSHIT_POOL_RT` пробует
`SCHED_FIFO` (на Android обычно отказ).

## ядра

- скалярный эталон — источник истины для тестов;
- NEON dotprod — горячий путь для `Q8_0`, `Q4_0`, `IQ2_S`, `IQ3_S`,
  `IQ3_XXS`, `IQ4_XS`;
- `Q4_K`, `Q5_K`, `Q6_K`, `BF16` идут через fallback; плотные веса
  переквантовываются в `Q8_0` при загрузке (`TOKSHIT_HOT_CONV`);
- диспатч выбирает NEON по `HWCAP_ASIMDDP`, без виртуальных вызовов;
- батчевые ядра (`dot_row_multi`, `run_bsegs`) переиспользуют строку весов
  для нескольких активаций;
- новое NEON-ядро принимается только вместе со скалярным сравнением.

Полные таблицы, раскладки и правила добавления ядра — в
[KERNELS.md](KERNELS.md).

## спекулятивный путь

`spec_loop.cpp` использует отдельный f16 KV-кеш (`Kv::alloc`, capacity
`TOKSHIT_SPEC_CTX`, по умолчанию 2048; 2К контекста ≈ 195 МБ).

1. Префилл идёт чанками по `maxb` (8) строк.
2. Черновик: первый токен берётся из полных логитов, следующие `K-1` — с
   урезанным роутером (`TOKSHIT_DRAFT_TOPK`, по умолчанию 2). Это lossy.
3. Verify: батч по кандидатам, полный роутер или `SPEC_VERIFY_TOPK`.
4. Принимается префикс, KV откатывается через `truncate_all(pos)`.
5. Жадный выход должен оставаться lossless при полном verify.

Известные проблемы:

- **контекст длиннее sliding-window (513) требует отдельной проверки.**
  На коротких промптах батч-путь корректен; длинные прогоны нельзя считать
  валидными без parity-теста;
- счётчики `c_expert_hit/miss` теперь считаются и в батчевом пути
  (`model_batch.cpp`), формат совпадает с single-путём;
- acceptance на полном verify измерен: 50–78 % на промптах до ~500
  токенов (`--spec --spec-k 3` — 0.93–1.00 tok/s), ids совпадают с обычным
  greedy байт в байт; `--spec-verify-topk 2` даёт ~50 % и ~1.5 tok/s,
  `--spec-fast` — 83 % и 2.09 tok/s (оба **lossy**). Всё это медленнее
  обычного top-6 с кэшем 512 МБ: 2.40 tok/s на холодном телефоне.

## ошибки

Без исключений. `Result<T>` — variant из значения или `Error`,
`TOKSHIT_TRY` — аналог `?`. Горячий путь ошибок не создаёт; только загрузчик
и токенизатор.

## тесты

doctest, по файлу на область: кванты, де-квант, GGUF, mmap, кэш, expert I/O,
пул, сэмплинг, токенизатор, KV, attention, батчевые ядра. Текущая линия —
161 кейс / 7715 проверок. Ядра и слои сверяются со скалярным эталоном из
`compute/kernels_scalar.cpp`.

## инварианты

- в `layer()` и `token_logits()` нет аллокаций;
- `rope_on_` и `swa_` имеют ровно `n_layers` элементов;
- `n_dense <= n_layers`;
- у каждого `Seg` `rows * rb <= bytes.size()`;
- бюджет кэша 0 легален и значит «не кэшировать»;
- hot-тензор не пересекает границу AHB-буфера;
- `reserve_ahb` не отдаёт последний 1 ГиБ `MemAvailable`.
