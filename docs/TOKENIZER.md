# Токенизатор и сэмплинг

Токенизатор — byte-level BPE в стиле GPT-2 с пре-токенизатором модели
Flint. Он читает словарь прямо из GGUF, работает с байтовыми строками и
умеет безопасно резать поток на границе UTF-8.

Смежное: [GGUF.md](GGUF.md) — ключи метаданных;
[CLI.md](CLI.md) — флаги сэмплинга; [RUNTIME.md](RUNTIME.md) — Forward.

## 1. Что читается из GGUF

```cpp
struct TokenizerMeta {
  std::vector<std::string> tokens;
  std::vector<std::string> merges;
  std::vector<uint32_t> token_types;
  std::vector<uint32_t> eog_tokens;
  uint32_t bos_token = NO_TOKEN;
  uint32_t eos_token = NO_TOKEN;
  bool add_bos = false;
  bool add_eos = false;
};
```

Ключи:

| ключ | назначение |
|---|---|
| `tokenizer.ggml.tokens` | словарь |
| `tokenizer.ggml.merges` | правила слияния |
| `tokenizer.ggml.token_type` | тип токена (обычный, special, byte) |
| `tokenizer.ggml.eog_token_ids` | токены конца генерации |
| `tokenizer.ggml.bos_token_id` | BOS |
| `tokenizer.ggml.eos_token_id` | EOS |

## 2. Byte map

GPT-2 представляет каждый байт `0..255` печатным Unicode-символом. Таблица
строится один раз:

- печатные ASCII и часть Latin-1 остаются собой;
- остальные байты получают кодовые точки начиная с `0x100`.

```cpp
struct ByteMap {
  std::array<char32_t, 256> to_char{};
  std::unordered_map<char32_t, uint8_t> to_byte;
};
```

Словарь хранится в байтовых строках, а не в Unicode: ключ `tokens_` —
`std::string` из байтов. Это убирает лишние преобразования на каждом
токене.

## 3. Пре-токенизатор

Вход режется на слова по классам:

| класс | примеры |
|---|---|
| `Letter` | буквы Unicode |
| `Number` | цифры |
| `Space` | пробелы, переводы строк |
| `Other` | пунктуация и символы |

Правила `next_word`:

- апострофы и сокращения не разрываются;
- число собирается не больше чем из 3 цифр;
- серия пробелов — отдельный кусок;
- перевод строки обрабатывается отдельно;
- слово начинается с одного ведущего пробела, если он есть.

Классы намеренно упрощены по сравнению с полным Unicode: модель обучена на
этом пре-токенизаторе, и отклонение меняет токены.

## 4. BPE

`encode_word` получает байтовую строку и сливает пары по рангу:

```text
word:  "hello"
пары:  h+e, e+l, l+l, l+o
merge: самая дешёвая пара по rank из merges
```

Таблица merge-рангов:

```cpp
std::unordered_map<std::string, uint32_t> merges_;
// ключ: left + '\0' + right, значение: rank
```

После слияний каждый кусок ищется в `tokens_`. Если куска нет, работает
байтовый fallback: каждый байт кодируется отдельным byte-токеном. Это
гарантирует, что любая строка кодируется, даже если словарь её не знает.

`decode` — обратная операция: id → байты → UTF-8. Для отображения
используется lossy-замена битых последовательностей на `U+FFFD`, чтобы не
сломать терминал.

## 5. Специальные токены

Модель использует:

| id | роль |
|---:|---|
| 150003 | `USER` |
| 150004 | `ASSISTANT` |

Промпт собирается как `USER + encode(text) + ASSISTANT`. В интерактивном
чате системная инструкция подставляется в начало следующего сообщения
(`/system`), а `/clear` очищает KV и позицию.

`encode_full` добавляет BOS/EOS, если это включено в метаданных. Обычный
`encode` — без них: чат и одноразовый промпт добавляют роли сами.

## 6. Сэмплинг

```cpp
struct SampleParams {
  float temperature = 0.8f;
  size_t top_k = 0;
  float top_p = 0.9f;
};

uint32_t sample(std::span<const float> logits, const SampleParams&,
                std::mt19937&);
uint32_t sample_utf8_safe(std::span<const float> logits, const SampleParams&,
                          std::mt19937&, const Utf8Buffer&);
```

Порядок:

1. `logits / temperature`; при `temperature = 0` — жадный `argmax`;
2. `exp` и нормировка;
3. top-k: `std::nth_element`, затем сортировка только `k`;
4. top-p: накопленная сумма по убыванию до порога;
5. розыгрыш `std::uniform_real_distribution<float>`;
6. до 8 попыток выбрать токен, который не ломает UTF-8.

`Utf8Buffer` хранит незавершённую последовательность между токенами.
Поэтому многобайтовый символ может быть выдан несколькими токенами, но в
stdout попадает только целый UTF-8.

Замечание о совместимости: максимум из логитов перед `exp` не вычитается.
Это сохраняет численный паритет с проверенным выводом; переполнение
ограничено диапазоном логитов модели.

## 7. Воспроизводимость

| ручка | эффект |
|---|---|
| `--temperature 0` | жадный argmax |
| `--seed N` | фиксированный `std::mt19937` |
| `--top-k N` | отсечка, 0 = выключено |
| `--top-p X` | nucleus, 1 = выключено |
| `--print-ids` | id в stderr для сравнения прогонов |
| `--dump-logits FILE` | f32-логиты для паритетного гейта |

Паритетный прогон: `--temperature 0 --seed 1 --print-ids`, затем сравнение
id двух реализаций. Логиты чувствительнее текста: `--dump-logits` ловит
расхождение, которое ещё не изменило токен.

## 8. Отладка

```sh
# показать, как строка режется на токены
build/tokshit --debug-tok <model.gguf> "привет, мир" 1

# сравнить id
build/tokshit --temperature 0 --print-ids <model.gguf> "hello" 8
```

`TOKSHIT_DEBUG_TOK=1` печатает id, байты и декодированный вид для первых
токенов словаря.

## 9. Ограничения

- Словарь и merges должны быть в GGUF; отдельного файла токенизатора нет.
- Нет агрессивной нормализации Unicode: вход кодируется как есть.
- Специальные токены не экранируются: текст пользователя может содержать
  последовательность, похожую на роль, но она кодируется как обычный текст.
- BPE не выделяет память в горячем пути генерации, но `encode()` промпта —
  холодный путь и может аллоцировать.
