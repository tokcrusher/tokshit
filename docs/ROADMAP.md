# Roadmap и инженерные заметки

`tokshit` — специализированный C++20 ARM64-рантайм для MoE-моделей больше
оперативной памяти. Вместо кроссплатформенного слоя — фиксированный
горячий путь под Snapdragon: NEON dot-product, AHB для плотных весов,
`O_DIRECT` для экспертов и послойный LRU-кэш.

Ниже — этапы, которые уже пройдены, текущие задачи и идеи. Идеи помечены
отдельно: они не входят в текущие результаты.

## 1. Текущий статус

| параметр | значение |
|---|---|
| обычный декод top-6, кэш 512 МБ | **2.0–2.7 tok/s** |
| декод top-6, кэш 1024 МБ, io 8 | **2.43 tok/s** (hit 60 % на длинных прогонах) |
| батчевый префилл (`TOKSHIT_PREFILL_BATCH=32`) | **4–5.3 tok/s** |
| `--fast` (top-2) | ~4.5 tok/s, **LOSSY** |
| спекуляция, lossless verify | acceptance 50–78 % на коротких раундах |
| AHB | 5.2 ГБ/с на потоке hot-весов, 25.7 на блоках 328 КБ |

Узкое место — не ядра, а поток плотных весов по 391 AHB-буферу
(~5.2 ГБ/с) и чтение экспертов с флеша (~1.4 ГБ/с). Ядра на отдельных
сегментах уже дают 25–35 ГБ/с.

## 3. Ближайшие задачи

### 3.1 Метрики спекуляции

- `c_expert_hit/miss` теперь считаются в батчевом пути (`model_batch.cpp`):
  `demand_async` вернул `true` — hit, иначе — miss; union-эксперты
  учитываются по числу заказанных срезов, формат совпадает с single-путём;
- 0 % acceptance на полном verify не воспроизводится: на текущем коде
  `--spec --spec-k 3` даёт 50–78 % принятых, `--spec-fast` — 83 %, и ids
  совпадают с обычным greedy байт в байт. Устаревшие нули в
  [SPEC_KV.md](SPEC_KV.md) сняты;
- реальный баг найден на другом месте: батч-путь ломается на контексте
  длиннее sliding-window (513) — prefill длинного промпта даёт взорванные
  логиты и мусорный декод. Короткие промпты (до ~500 токенов) корректны;
- сравнение `--spec` с обычным greedy на одинаковом префиксе сделано:
  паритет подтверждён на «hi»/24 токена и на русском промпте/12 токенов.

### 3.2 Поток плотных весов

- слить последовательные matvec'и без барьеров пула и укрупнить row-чанки
  задач: пер-op накладные расходы — главный съедатель полного прохода;
- попробовать крупные AHB-буферы (64–256 МБ) вместо 391 буфера по тензору;
- проверить Q6_K/Q5_K NEON-ядра вместо конверсии в Q8_0: 1.36 ГБ вместо
  1.74 ГБ плотных (−22 % полосы);
- измерено и отклонено: `TOKSHIT_HOT=0` (mmap-dense) — page cache плотных
  весов вытесняется, 0.8–1.6 tok/s против 2.1–2.2 у AHB;
- f16 KV на декоде: −50 % полосы attention на длинных контекстах.

### 3.3 Кэш экспертов

- cross-layer gate prediction (Fate): гейт слоя i+1 на hidden слоя i —
  точность предсказания top-6 79–97 %; prefetch-кольцо на 2–3 слоя;
- shallow-favoring кэш: слои 0–3 целиком (1.33 ГБ → hit 99 % на них),
  eviction ARC/Least-Stale вместо чистого LRU;
- sidecar-layout: gate|up|down одного эксперта слитно — один pread ~2 МБ
  вместо трёх мелких; UFS на крупных чанках даёт 3.5–4.2 ГБ/с;
- проверить `--pin-experts` на длинном прогоне и `TOKSHIT_PIN_EVERY` при
  дрейфе роутинга.

### 3.4 Prefill

- bulk-streaming префилл: стриминг целых слой-блоков (~333 МБ) последовательно
  + батч-GEMM 8×8 → I/O-потолок ~77 tok/s при T≥512;
- union-GEMM по экспертам: одна строка веса деквантуется один раз на чанк;
- hit-rate префилла в метриках (сейчас prefill-попадания не учитываются).

### 3.5 Сравнение с универсальными движками

- одинаковый GGUF, одинаковый промпт, `temperature 0`;
- одинаковое число потоков и кэш;
- сравнение по tok/s и по качеству (id/логиты).

Это отдельная задача: цифры должны быть воспроизводимыми, а не
маркетинговыми.

## 4. Идеи, не реализованные

> Всё в этом разделе — гипотезы. Они не входят в текущий результат.

### 4.1 Спекуляция одной моделью

Draft-режим уже есть: `--draft-topk 2` читает меньше экспертов. Дальше
нужен батч-verify:

- `Seg` с массивом `ActQ8` на токен;
- один эксперт применяется к нескольким токенам за проход;
- цикл: draft K токенов → verify одним батчем → принять префикс → откатить
  KV.

Ограничение: эксперты у каждого токена свои, поэтому чтение с флеша не
делится между токенами. Батч экономит только плотные веса (~40 % цены
токена). Оценка ускорения — 1.15–1.35×, требует замера.

### 4.2 CECAR-подобное смещение роутинга

Предсказывать, когда эксперт понадобится снова, и немного смещать логиты
в сторону экспертов, которые уже в кэше. Идея меняет выход модели, поэтому
это **LOSSY**-путь. Цель — поднять hit-rate выше ~46 % при кэше 4 ГБ.

### 4.3 Меньше ядер ради энергии

Декод memory-bound. Если те же tok/s достигаются на 3 ядрах вместо 6–7, то
меньше тепла, троттлинга и расход батареи. `scripts/ab.sh` уже умеет
сравнивать конфиги.

### 4.4 Батчевый prefill — реализовано

Префилл идёт батчами `TOKSHIT_PREFILL_BATCH=32` (по умолчанию) через
`token_logits_batch`: веса читаются один раз на чанк, эксперты — union'ом
роутинга чанка. Замеры: 5.28 tok/s на промпте 115 токенов, 3.96 tok/s на
382 токенах (union растёт с длиной промпта — упор во флеш). Дальше —
bulk-streaming слой-блоков (§3.4).

## 7. Эскиз горячего пути

```cpp
void Model::layer(size_t l, Workspace& ws, KVCache& kv,
                  std::span<const std::pair<float, float>> rope) {
  const Layer& lt = layers_[l];
  rmsnorm(ws.hn, lt.attn_norm, eps_);

  // один барьер на q/k/v
  run_segs({seg(&lt.attn_q, ws.hn, ws.q),
            seg(&lt.attn_k, ws.hn, ws.k),
            seg(&lt.attn_v, ws.hn, ws.v)}, 16);

  for (size_t h = 0; h < n_heads_; ++h)
    rmsnorm(span(ws.q).subspan(h * head_dim_, head_dim_),
            lt.attn_q_norm, eps_);
  for (size_t h = 0; h < n_kv_; ++h)
    rmsnorm(span(ws.k).subspan(h * head_dim_, head_dim_),
            lt.attn_k_norm, eps_);

  if (rope_on_[l]) { /* rope_apply по головам */ }
  kv.append(l, ws.k, ws.v);

  attention_core(l, ws.q, kv, ws.attn);  // scores, sink, softmax, V
  matvec(lt.attn_o, ws.attn, ws.o);
  for (size_t i = 0; i < hidden_; ++i) ws.x[i] += ws.o[i];

  rmsnorm(ws.hf, lt.ffn_norm, eps_);
  if (l < n_dense_) {
    dense_ffn(lt, ws.hf, ws.x);
  } else {
    moe_ffn(lt, l, ws.hf, ws.x);  // router, load, phase A/B, shexp
  }
}
```

## 8. Риски

| риск | мера |
|---|---|
| ошибка в NEON-ядре | тест против скаляра до интеграции, `vcheck` на GGUF |
| нет `FEAT_DotProd` | runtime-детект `HWCAP_ASIMDDP`, скалярный fallback |
| разное поведение `exp`/`softmax` | без `-ffast-math`, сравнение логитов |
| расхождение IQ-декванта | формулы 1:1, тесты на известных блоках |
| Android-ограничения (`mlock`, page cache) | best-effort-семантика, `madvise` |
| `shared_ptr` в горячем пути | `ExpertRef` с raw-указателем, владение только при копии |
| OOM на 15.2 ГБ | `safe_run.sh`, кэш 512 МБ, один процесс модели |
