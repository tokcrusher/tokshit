# Производительность

Цель проекта: decode ≥ 15 tok/s и prefill ≥ 50 tok/s на Flint-40B-A2.5B,
top-6, lossless, на целевом телефоне. Цель не достигнута. Ниже текущие
замеры, бюджет токена и физические ограничения устройства.

## 1. Текущие замеры

| режим | tok/s | условия |
|---|---:|---|
| normal top-6, 8 токенов | **2.40** | 47 °C, кэш 1024 МБ, io 8 |
| normal top-6, 16 токенов | **0.96** | 60 °C, тот же конфиг |
| normal top-6, 2 токена | 1.63 | 47 °C, холодный кэш |
| `--turbo` (top-2 + Q4_0, **LOSSY**) | **3.52** | 50 °C |
| prefill union, T=224, батч 32 | **4.53** | 49.4 с |
| prefill union, T=128 | **6.01** | 21.8 с |
| prefill-bulk, T=224 | 2.32 | 96.5 с |
| спекуляция, полный verify (lossless) | 0.93–1.0 | acceptance 50–78 % |

Исторические длинные прогоны давали 2.0–2.7 tok/s. Разброс объясняется
температурой, а не изменением кода. `--turbo` меняет выход модели и не
заменяет обычный декод.

## 2. Методика

- Устройство: Snapdragon 8s Gen 4 (SM8735), 1× Cortex-X4 + 7× Cortex-A720,
  15.2 ГБ RAM, Android/Termux, UFS.
- Модель: `flint-UD-Q3_K_XL.gguf`, 18.49 ГБ, 49 слоёв, 256 экспертов,
  top-6, hidden 2048, ffn эксперта 512, shared 1024.
- Запуск: `scripts/safe_run.sh`, один процесс, `MemAvailable > 4000` МБ
  перед стартом, AHB ≤ 4096 МБ, кэш ≤ 2048 МБ.
- Обязателен `termux-wake-lock`. Без него Android усыпляет процесс.
- Температура: cpu-зоны 46–72 °C. При 60 °C и выше частоты падают до
  1.2–1.7 ГГц, поток плотных весов — с 12.6 до 4.2 ГБ/с.
- Замер без температуры, wake lock и числа токенов недействителен.
- Сравнение конфигов — только вперемешку, через `scripts/bench_matrix.sh`.

## 3. Бюджет токена

`qstat` по модели:

| роль | ГБ |
|---|---:|
| эксперты | 16.945 |
| attention | 0.891 |
| output | 0.327 |
| embedding | 0.327 |
| всего | 18.49 |

Один токен normal top-6:

- плотные веса после Q8_0: **1.74 ГБ**;
- эксперты: 6 из 256 × 3 проекции × 47 слоёв = **0.377 ГБ**;
- итого **2.12 ГБ/токен**.

Цель 15 tok/s означает 66.7 мс на токен и устойчивые **31.8 ГБ/с** при
100 % попадании экспертов. Измеренная устойчивая полоса: 4.2–12.6 ГБ/с.
Разрыв не закрывается настройками кэша.

## 4. Плотные веса

Hot-веса пакуются в 52 сегмента по 32 МБ (`TOKSHIT_HOT_SEG_MB`). Один
большой AHB-буфер gralloc не выдаёт, а буфер на каждый тензор даёт 391
mapping и лишние TLB-промахи. Сегменты — компромисс.

| путь | ГБ/с |
|---|---:|
| Q8_0 matvec на сегментах | 25–35 |
| полный поток hot-весов через AHB, холодный телефон | 5.2 |
| тот же поток, 60 °C | 4.2 |
| поток через malloc | 21.7 на блоках, но страницы уходят в reclaim |

Разрыв между 25–35 ГБ/с на сегментах и 5.2 ГБ/с на полном потоке — главное
узкое место декода. Причина — не ядра, а троттлинг и стоимость обхода
1.74 ГБ каждый токен.

## 5. Эксперты

Экспертный путь читает 0.377 ГБ на токен при полном промахе. Реальная
полоса зависит от кэша и температуры:

| путь | ГБ/с |
|---|---:|
| Iq-ядра на блоках | 4–20 |
| AHB-блоки 328 КБ | 25.7 |
| последовательное чтение UFS | ~1.4 |
| O_DIRECT на крупных чанках | 3.5–4.2 |

Кэш 512 МБ — рабочая точка. Кэш 2–3 ГБ поднимает hit-rate на 8 п.п., но
tok/s не растёт: память уходит в reclaim. `TOKSHIT_AHB_USAGE=often` на этом
устройстве медленнее (3.1 против 5.2 ГБ/с).

## 6. Prefill

Prefill T=512 требует прочитать регион экспертов всех слоёв, около 16 ГБ.
При UFS 1.4 ГБ/с это 11.4 с только на I/O, то есть 45 tok/s до вычислений.

Union-путь читает меньше: при T=224 около 100 экспертов на слой. Он даёт
4.53 tok/s. Bulk-путь читает весь регион слоя (325–379 МБ) и копирует
120–160 МБ; на T=224 это 2.32 tok/s, хуже union. Sequential-полоса не
окупает лишние байты.

## 7. Что проверено и отклонено

| изменение | результат |
|---|---|
| hot-веса: 391 буфер → 52 сегмента по 32 МБ | dense microbench 14.5 → 17.7 ГБ/с; decode в шуме |
| fusion router + shared gate/up | минус два барьера на MoE-слой |
| `--turbo`: top-2 + Q4_0 + кэш 1024 + O_DIRECT | 3.52 tok/s, LOSSY |
| prefill-bulk | opt-in, хуже union |
| mmap-dense (`TOKSHIT_HOT=0`) | page cache не держит 1.74 ГБ, 0.8–1.6 tok/s |
| кэш 2–3 ГБ | hit-rate +8 п.п., tok/s без роста |
| i8mm (`TOKSHIT_I8MM=1`) | в пределах шума, включается вручную |
| двухстрочные IQ (`TOKSHIT_IQ2ROW=1`) | 0.53 tok/s против 2.40 |
| спекуляция полным verify | расширяет union экспертов, медленнее normal |

## 8. Почему 15/50 не достигнуты

1. Плотные веса 1.74 ГБ читаются на каждом токене. При 12.6 ГБ/с это
   138 мс, уже меньше 7 tok/s.
2. Эксперты добавляют 0.377 ГБ и 200–700 мс на нагретом телефоне.
3. Телефон троттлит через несколько секунд нагрузки. На 60 °C dense
   падает до 4.2 ГБ/с, экспертный путь — до 0.5–2 ГБ/с.
4. Prefill упирается в UFS и в полный регион экспертов.
5. 15 tok/s требуют 31.8 ГБ/с устойчиво. Измеренный потолок устройства
   ниже.

Дальше нужны другие рычаги: Q6_K/Q5_K ядра вместо конверсии в Q8_0,
sidecar-layout экспертов, i8mm GEMM для префилла, внешнее охлаждение.
Без смены одного из этих условий 15/50 остаются недостижимыми.

## 9. Воспроизведение

```sh
termux-wake-lock
TOKSHIT_MIN_AVAIL_MB=1800 scripts/safe_run.sh env GGUF_TIME=1 \
  TOKSHIT_PROF=1 build/tokshit --temperature 0 --cache-mb 1024 \
  --io-threads 8 --pool-workers 7 MODEL "привет" 8

TOKSHIT_MIN_AVAIL_MB=1800 scripts/safe_run.sh build/tokshit --turbo \
  --temperature 0 MODEL "привет" 8

TOKSHIT_PREFILL_BATCH=32 scripts/safe_run.sh build/tokshit --temperature 0 \
  --cache-mb 1024 --io-threads 8 --pool-workers 7 \
  MODEL --prompt-file /home/prompt128.txt 1
```

Перед замером проверьте `/sys/class/thermal/thermal_zone*/temp` и
`MemAvailable`. После прогона дайте телефону остыть.
